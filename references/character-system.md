# 角色设计与生图方法

在 `SKILL.md` 已经选择创建、导入或修改角色后读取本文件。它只负责把身份线索变成可生成、可检查的角色设计；选择、保存、升版和最终停止仍回到 `SKILL.md`。

## 1. 先确定美术锚点

IP 角色首先是一套能够被反复看见、反复画出并跨作者保持一致的视觉识别，不是一张靠异常结构证明原创性的概念图。开始设计前先确定角色来自谁、观众已经用哪些视觉线索认识它，以及哪些线索换了画师、服装、姿势和场景仍必须保留。

美术锚点依次来自用户明确指定的形象要求、用户提供的官方材料、官方长期使用的标志和主色，以及已经稳定重复并被公众识别的二创共识。品牌或作品已有的常见颜色、动物原型、拟人部件和标志形态属于认知资产；只要它们承担来源识别，就不因为常见而需要回避。人物经历、品牌理念和故事寓意可以影响性格与气氛，但不能取代视觉锚点，也不能为了把寓意画出来而强行改变人体结构。

同一角色可以由数个简单锚点共同成立，不要求压成一个夸张主轮廓或一个前所未见的部件。稳定锚点应当能够在头像尺寸被看见、在不同动作中继续存在、被不同画师自然复现，并在去掉名称与 Logo 后仍帮助观众联想到来源。除此之外的发型细节、服装款式、眼型、表情、姿势、装饰和画面气氛属于自由设计层；原创性发生在这些锚点怎样组合成有性格的角色，而不是抛弃锚点另造一个陌生物种。

拟人角色默认保持自然、亲和且容易复画的人体基型。动物或物件特征优先沿用公众熟悉的拟人语言，例如耳、角、尾、发型轮廓、配色、纹样、服装形态或随身标志。来源本身没有异常身体结构、用户也没有明确要求时，不为了增加辨识度改造四肢、器官和人体连接方式。

已有图片用于导入时，分别记录：

- 用户明确要求保留的身份特征；
- 多张图中稳定重复的视觉特征；
- 只由当前姿势、光线、背景或一次生成造成的偶然细节。

前两类进入角色档案，第三类只服务当前判断。无法确定一项细节是否属于身份时，把它作为一个具体选择交给用户。

## 2. 默认发展一个完整方向

材料足够时，Agent 把用户原始目标、用户提供的材料、已经确认的美术锚点、必要输出形式和用户硬边界直接交给图像模型，由图像模型在锚点之内完成一张完整角色形象。默认结果不是方向卡、选项题或候选组；不要为了显得稳妥而同时画三个人物，也不要在角色出现前把自由设计层预先拆成脸、发型、服装、材质或装饰并写进角色档案。

只有用户明确要求比较时才建立多个方向。所有方向共享同一组固定美术锚点，只在自由设计层形成真正不同的角色表达；不能通过丢掉主色、物种拟人特征或公共识别形象来制造差异。分支之间不读取彼此的图片或描述。用户没有要求比较时，否定当前设计只表示根据其具体反馈重做这一条，不自动增加候选、评审或投票阶段。

### 极简手绘 IP 方向

当用户想要轻量内容插画、低制作负担、高频复用，或明确选择极简手绘方向时，可以把它作为当前单一方向；它不是所有角色的默认画法。角色设计必须把简约落实为角色结构，而不只写“线条简单”：

- 保留来源识别所需的美术锚点组合，只简化画法，不另造异常轮廓或身体部件；
- 主体以黑色实形或清楚线形承载身份，强调色只承担动作、问题、结果或提示中的一种职责；
- 表情克制，情绪主要由身体角度、动作方向和对象反馈表达，不靠复杂五官或萌系装饰；
- 手、爪、附肢或标志物必须适合反复执行拿、推、拉、接、挡、连、拆、压等内容动作；
- 绘制方式使用白底、细而略有手绘感的黑线、平涂和极少纹理，避免渐变、厚重体积光、复杂背景与装饰性高光。

选择这一方向后，首次正常比例形象图同时做“动作识别测试”：让角色用一个低技术物件完成与其定位有关的动作。缩略图中应先看懂角色在做什么，再注意服装和表情。若必须靠文字、姿势说明或额外道具墙才能理解，说明动作词汇或轮廓仍不够清楚。

已有角色已经锁定精细画法时，不因某张衍生图选择极简视觉语言就改写 `character-profile.json`。只有用户明确要建立新的角色画法，才返回本流程修改绘制方式、重画主参考图并升版。

## 3. 第一张角色形象图

从零设计时，第一张图出现前不存在 `character-profile.json`。Agent 只准备一份实际交给图像模型的简洁创作输入，保留用户原话、完整材料、正常比例全身动漫形象这一必要形式和用户明确边界，不添加设计理由、失败归因、完整角色结构、精确色值、正侧背说明或验收清单。提示词和图片输入先完整展示给用户，获确认后原样生成一张正常的动漫角色形象图。它同时承担设计确认和主参考候选，不先生产 Q 版或中性设定稿。图片使用：

- 单角色、完整全身和用户要求的正式比例；用户未指定时使用适合当前动漫形象的正常比例；
- 能体现角色性格与已确认美术锚点的有张力姿态、明确重心、有表现力的表情和富有动势的构图；
- 足以辨认脸部、服装、材质、连接关系与身份标志的清楚画面；
- 简洁但允许必要气氛的背景，不做设定表、多视图或中性站桩。

用户和来源已经确定的美术锚点必须保留；发型细节、服装、表情、姿态和构图等自由层由图像模型根据这份创作输入共同判断，不由维护侧先写成角色档案再让图片照着复现。检查时同时看完整画面和缩略图：观众应先认出来源关联和基本角色原型，再感受到这一次的具体设计；精致、复杂、罕见或夸张本身都不构成通过标准。此时只依据用户确认的要求、美术锚点与真实图片判断，不拿尚不存在的档案反向判错。

Q 版不是角色身份创建的默认阶段。只有用户明确要求把角色本身设计成 Q 版时，才把 Q 版比例写入档案并生成相应主图；后续桌宠或小尺寸运行素材只消费已锁定身份，不反向把正常比例主参考图改成 Q 版。

## 4. 把选择拆成可复原结构

当前单一设计确定或现有形象获认可后，才创建 `character-profile.json` 并逐项填写脚本当前 schema。档案从获批图片和用户已确认要求中提取身份，把来源美术锚点和承担稳定角色识别的具体表达写入固定边界；不把被否定的图片、此前提示词里的未实现细节或维护侧设计理由写成角色事实。完成标准不是“描述看起来丰富”，而是另一位 Agent 不需要发明身份关键细节，就能画出同一角色的正面、侧面和背面。

按以下顺序拆解：

1. **形体骨架**：形态类别、物种或原型、年龄感、体型、头身比例和缩略图轮廓。
2. **头脸结构**：头型、顶部结构、毛发或发型轮廓、五官布局、眼眉、鼻口、口鼻部和固定纹样。位置关系应能指导绘制，不只写“大眼睛”“可爱”。
3. **身体结构**：颈肩、躯干、四肢、手爪、腿足，以及尾巴、翅膀、角、触须等附肢的数量、根部、静止路径、末端和运动方式。
4. **颜色地图**：每个颜色有稳定 ID、十六进制值、职责、准确落点和面积关系；纹样另写所在区域、几何边界和使用的颜色 ID。
5. **材质地图**：毛、皮肤、布料、金属、木、玻璃或发光体分别覆盖哪里，边缘如何交接，表面是哑光、柔软、粗糙、半透明还是高光。
6. **服装结构**：每一层的覆盖范围、版型、颜色、材质、扣合或悬挂方式、边缘与缝线，以及正面、侧面和背面的可见形态。没有服装时也明确由身体表面构成。
7. **标志性元素**：逐项写含义、几何、相对尺寸、颜色、材质、连接方式、身体落点、各视角可见性和运动方式。连接方式必须能回答“它究竟长在角色上、穿在角色上，还是由环、绳、扣、链独立悬挂”。
8. **视角模型**：正面、侧面、背面各自说明轮廓与层级；写清身体、服装、附肢和配件谁在前、谁在后、何时遮挡，以及跨角度仍可识别的锚点。
9. **绘制方式**：风格类别、形状语言、线条、色彩处理、光影、纹理和细节密度分别记录。它们控制画法，不承担角色身份细节。

无法从正面图直接看见的背面、接缝或连接细节，由 Agent 补成结构上最简洁、与已确认轮廓一致的方案，并在 `provenance.decisions` 标记为 `agent_inferred`。只有会改变轮廓、脸部、主配色、标志物或象征含义的选择才交给用户。

完整性检查采用以下反事实：如果移除主参考图，档案是否仍能让另一位 Agent 说清角色的头、身体、四肢、附肢、服装每层、每种颜色、每种材质和每个标志物怎样连接；如果换成侧面或背面，是否还需要临时猜测身份细节。任一答案为“需要猜”时，先补档案。

## 5. 档案与生图输入

`character-profile.json` 只在主参考候选获批准后建立。它是角色身份的结构化档案真源，获批图片是默认视觉真源；两者共同供后续一致性、场景、动态和桌宠任务读取。普通下游生图主要用主参考图保持身份，不再复制完整档案。

档案中的变化边界分为：

- `consistency.fixed`：每张图都要保留的身份特征。
- `consistency.flexible`：表情、姿势、场景以及用户允许的非身份变化。
- `consistency.revision_required`：改变后必须重画主参考图并升版的特征。

`fixed` 和 `revision_required` 只保存指向档案字段的路径，例如 `$.signature_elements`，不复述字段内容；说明书和生图输入在使用时从这些路径读取当前值。这样颜色、结构或标志物只在一个位置修改。`flexible` 记录不属于角色身份的当次变量，可以直接使用自然语言。

当次姿势、动作、场景、镜头、画幅和尺寸只有用户明确要求或固定生产协议确实需要时才通过 `prompt --task` 加入，不写回角色档案。脚本输出实际完整 `prompt`，锁定角色时还会返回经过校验的 `master_reference`。先向用户展示提示词和图片输入并停止；确认后下一轮才原样交给生图能力。

图片中出现意外但优秀的细节时，先判断它是身份结构还是本次画面的偶然表现。身份结构只有在用户批准后才写回相应字段；偶然光影、褶皱和摆动留在当次图片中。

## 6. 正式主参考图

正式主参考图的作用是让后续 Agent 看清并感受到角色本身。默认直接采用用户认可的第一张正常比例动漫形象图：单角色、完整全身，以有张力的姿态、明确重心、富有动势的构图和有表现力的表情呈现角色；背景简洁但允许支持气氛的必要环境。图片获批后再从它建立档案，不为迁就后来填写的字段重新生成另一张主图。

`character_kit.py prompt <draft> --purpose master` 只服务已有形象或既定档案的主图恢复与重绘：脚本验证已经确定的档案，并组合重建当前角色所需的身份锚点。它不参与从零设计，也不能为了调用该命令而在第一张图前建立完整档案。

正式图获批后成为角色包中唯一默认视觉参考；未获批的旧尝试只留在工作区，不进入角色包，也不影响后续生成。

## 7. 配色与复杂部件

用户否定配色时，从相同的形体、脸部和标志物建立配色分支。每个方案重新分配主色、辅助色和强调色，并写清颜色落点与面积关系，不在上一张图上连续叠改。用户确认后，将颜色及其覆盖地图一起写回档案。

同一服装、饰品或身体部件连续两次生成错误时：

1. 从档案提取该部件的几何、比例、颜色、材质、连接、各视角可见性和运动方式；
2. 单独生成或描述一份只服务该部件的清楚结构；
3. 从正面、侧面和连接受力关系检查它是否成立；
4. 把获确认的结构写回对应身体、服装或标志物字段，并更新一致性边界；
5. 由脚本重新生成完整提示词，再生成整张角色图。

部件设计图只在用户明确要求保留时进入角色包；默认完成整角修正后停止使用。

## 8. 自动视觉检查

首次形象图先看真实的用户结果：来源美术锚点是否完整保留，去掉名称与 Logo 后是否仍能建立来源联想，人体与拟人特征是否自然易懂，换动作、服装或画师后是否仍有同一个基本形象，以及图片本身是否技术完整。不要用“结构是否罕见”“轮廓是否足够夸张”或“寓意是否被逐项画出”代替这些判断。

角色建档后的图片再检查头脸位置、身体比例、颜色落点、纹样边界、服装层级、材质区域、标志物和必要附肢是否符合档案，当前角度的遮挡是否符合 `view_model`。失败时先判断档案是否缺项；档案已明确时再重画。只有纯渲染错误可以局部修复，修复后重新检查身份锚点和全部结构。

## 9. 一致性测试

一致性测试先运行 `prompt <draft> --purpose consistency --reference <approved-master>`，展示脚本输出的提示词和主图并等待确认；下一轮才同时交给生图能力。提示词只说明本次变化，身份由主图承担。临时改变姿势、表情和简单背景，并比较：

- 外轮廓、头身比例和附肢连接；
- 脸部或拟脸区域的几何与位置；
- 每种颜色的落点与面积关系；
- 服装的层级、扣合、边缘和背面延续；
- 标志物的几何、相对尺寸、连接和摆动；
- 绘制方式和材质表现。

测试失败时，先补足含糊的生产者字段；档案已经明确但图片仍漂移时，重新生成更清楚的主参考图。测试图不进入正式角色包，也不成为下一次测试的参考。

## 10. 条件式辅助校准板

单张主参考图仍是唯一图片身份真源。只有同一类角度、动作、手部或配件漂移在同一角色版本上连续失败至少两次，而且档案与主图已经明确时，才建立一张辅助校准板。先运行：

```text
python scripts/character_kit.py calibration-prompt <kit-folder> --output <job-json> --calibration-id <slug> --kind <turnaround|action|hands|accessory> --failure-note <两次可见失败> --attempts <count>
```

先展示 `job-json` 中的完整 `prompt` 和 `master_reference` 并等待用户确认；下一轮才通过已经选定的图像入口原样生成。校准板只解决被记录的失败：`turnaround` 展示正、严格侧、背三视角，`action` 展示相关动作关键姿态，`hands` 展示静止、抓握、指向和施力，`accessory` 展示配件各面与连接方式。它不能新增身份细节，也不能成为更高优先级的参考。

实际打开图片，确认所有格是同一角色、没有新增结构，且失败部位比前两次更明确后运行：

```text
python scripts/character_kit.py register-calibration <kit-folder> --job <job-json> --image <approved-image> --qa-note <可见依据>
python scripts/character_kit.py calibration-references <kit-folder> --kind <kind>
python scripts/character_kit.py check <kit-folder>
```

下游只有在当前任务确实涉及该失败类型时，才把返回图片作为 `character-calibration` 参考加入视觉简报；不要默认把所有校准板塞进每次生图。记录绑定角色 revision、档案 hash 和主图 hash，角色升版后不会再由 `calibration-references` 返回。旧记录仍保留用于追溯，但不能修改身份或替代主参考图。
