# IP 衍生视觉生产方法

在 `SKILL.md` 已确认用户要用现有 IP 角色制作头像、主页横幅、资料卡、文章封面、说明图或正文插图后读取本文件。它负责视觉简报、生图、检查和归档；角色身份仍由 `character-profile.json` 与其中登记的单张主参考图决定。

## 1. 先建立可执行的视觉简报

运行 `python scripts/visual_kit.py schema` 读取当前合同，需要文件草稿时运行：

```text
python scripts/visual_kit.py draft <brief-path> --kind <kind> --visual-id <slug> --language <language>
```

Agent 从当前内容和用户提供的资料直接填写草稿。用户不需要写提示词、JSON 或文件名。简报只记录当前图片的传播任务：

- 内容真源：当前文章、段落、项目资料或用户已确认的主页定位。
- 核心对象：观众第一眼应该认出什么。
- 理解缺口：观众原本不明白什么。
- 机制或变化：哪个动作、关系或转变使结论成立。
- 看后结论：观众最终应该记住什么。
- 品牌角色：品牌是主题核心、辅助案例还是不参与。
- 结构选择：画幅、唯一主要图解结构、标题、标签、结论和配色。
- 角色动作：角色担任什么作用，亲自影响哪个对象，产生什么可见结果。
- 图片资料：除角色主参考图以外的 logo、界面、数据、物品或视觉资料及其作用。
- 视觉语言：沿用角色画法，或为封面、说明图、正文插图选择一套明确的内容视觉语言。

先用四个问题压缩内容：画面围绕什么具体对象，观众卡在哪里，什么动作或关系使它发生变化，看完以后只记住哪一句。再确定唯一视觉中心、信息先后、前中后景和角色动作。简报中的每项判断标记为用户确认或 Agent 推断。只有名称、立场、事实或品牌方向无法从材料确定，而且不同答案会改变最终叙事时，才把一个具体取舍交给用户；画幅、结构、标题、动作和排版默认由 Agent 决定。

## 2. 角色与资料怎样进入生图

运行：

```text
python scripts/visual_kit.py prompt <character-kit> --brief <brief-path>
```

脚本先验证角色包和视觉简报，再从角色档案生成完整身份描述。命令输出的 `image_references` 已按顺序列出单张主参考图和其它资料，输出的 `prompt` 是本次唯一生图输入；Agent 用 `SKILL.md` 已选择的图像入口实际执行两者。

角色身份和当前画面职责分别处理：

- 档案与主参考图决定轮廓、比例、脸部、颜色落点、服装连接、材质和标志物。
- 视觉简报决定动作、场景、画幅、镜头、信息结构和本次文字。
- 当前图片中偶然出现的衣饰、纹样和配件不写回角色档案。
- 衍生图不会成为新的角色参考图。用户明确要改变身份特征时返回角色修改流程，升版后再重新生成衍生图。

每张图片输入只承担一种明确职责：角色主参考图负责身份，用户当前提供的 logo 负责准确品牌标记，构图或界面资料负责当前页面关系。内置视觉语言可以由 JSON 提示词档案或完整参考图包承担，实际采用哪一种由该视觉语言自己的正式入口决定。脚本最终生成一条提示词，顺序固定为“图片职责、主体与动作、环境、构图、光色与材质、准确文字和 logo、最少必要限制”。分析过程、备选方向和 QA 检查表不塞进提示词；不使用与当前失败无关的通用负面词清单。

### 极简手绘内容视觉

“极简手绘 IP”是封面、说明图和正文插图可选的内容视觉语言，不是头像、主页视觉或所有角色的全局默认值。用户明确选择，或当前任务确实需要低信息密度、强隐喻和高频复用时再采用。已有角色仍保留主轮廓、脸部锚点、主配色落点和标志物；若极简化会改变这些固定身份特征，先返回角色修改流程建立新版本，不能在衍生图里偷偷改画法。

选择后，先把内容压成一条因果链：

1. 从内容中只取一个最值得看见的关系或变化，并改写成一个动作词；
2. 选择一个观众不需要说明就懂的低技术物件或装置承载它；
3. 让角色亲自推、拉、接、挡、连、拆、压、倒入或取出对象；
4. 用物体位置、流向或前后状态显示结果，文字只做最后补充。

画面采用一个连续的物理场景，不使用卡片墙、仪表盘、网页界面、嵌套边框或彼此独立的小插图拼盘。主体与核心装置合计约占画面四成至六成，至少保留约三成五的空白；以白底、细而略有手绘感的黑线和平涂为主。黑色负责角色和结构，额外二至三种颜色分别只承担流动、问题或结果、提示等明确职责。标签只贴近对象出现，优先二至八个中文字；一张图通常不超过五至八处短文字。避免渐变、投影、体积光、写实纹理、复杂环境和没有因果作用的装饰图标。

启用时先运行：

```text
python scripts/visual_kit.py style-references minimal-handdrawn
```

把命令输出的 `brief_references` 原样写入视觉简报的 `references`。这些绝对路径由脚本从内置资源清单生成，避免简报位于其它目录时解析到错误位置。图片只校准留白、线条密度、色彩职责和角色参与方式，不提供新图的构图；必须从当前内容重新选择动作、物件和空间关系。来源与许可见命令输出的 `source_notice`。`visual_kit.py` 会根据统一的 reference role 切换生图合同，并把完整案例作为实际图像输入传下去。不要只在 `style_notes` 写“简约”，那不会启用这套视觉语言。

### OKX Editorial 品牌编辑视觉

用户要求 OKX 风格，并且作品使用已锁定 IP 角色时，运行：

```text
python scripts/visual_kit.py style-profile okx-editorial
```

把视觉简报的 `visual_language` 设为 `okx-editorial`。命令返回 `style-profile.json` 的已验证内容、绝对路径和 SHA-256；脚本在生成提示词时读取同一文件，并在归档时保存本次 JSON 快照与哈希。七张来源案例和透明 Logo 留在资源目录中用于追溯提炼依据，不参与默认生成。

正常 OKX 风格生成的 `image_references` 只有角色主图和当前任务确实需要的资料。用户明确要求精确 OKX Logo 时，再把已保存的透明 Logo 作为当前品牌素材加入简报；普通风格请求不自动加载它。颜色职责、标题层级、场景模式、角色融合、内容边界和成片检查全部以 JSON 为准，本文不维护第二份参数清单。

JSON 会随内容一起进入唯一提示词，模型根据当前主题从其中选择一种主场景。来源案例中的旧文案、数字、行情、界面、地点、吉祥物和物件组合不会被读取，也不会进入新图。完整运行真源、面向维护者的说明和来源分别见命令输出的 `profile_path`、`style_guide` 和 `source_notice`。

## 3. 头像、主页横幅和资料卡

### 头像

默认生成一张 `1:1` 源图，让角色头部或头肩居中，核心轮廓、眼睛、表情、领口和标志物在小尺寸仍能辨认。主体完整落在圆形裁切安全区，因此同一源图可以同时用于圆形和方形平台。

`badge` 适合缩略图较小的平台：使用扁平色块、清楚线条和三至五种主色。`portrait` 适合展示面积较大的平台：允许更丰富的光影与材质，但保留同一轮廓和识别顺序。用户只说“做头像”时，Agent 根据主要平台推荐并生成一种；用户说“头像套图”时生成两种并分别归档。

### 主页横幅

未指定平台时使用 `3:1` 通用主页横幅，并给左下头像遮挡区留出空间。用户指定平台且提供页面截图或尺寸时，以资料中的实际裁切、头像和按钮位置为准。角色使用半身、头肩或动态回眸进入一个品牌叙事，并与核心符号发生真实互动；右侧文字只保留一句名称、定位或标语。

需要平台当前规格且用户没有提供资料时，先查询该平台的官方尺寸与安全区。规格只影响当前视觉简报，不写入角色档案。

### 资料卡

默认使用 `4:5` 手机端构图。名称和一句定位进入第一视觉层，二至四个短标签只呈现稳定身份线索。角色通过一个真实动作把象征物带入信息结构，背景和装饰服从角色与文字层级。

完整角色档案只用于保持身份，不把三视图、配色表、结构清单或生图说明画进资料卡。

用户说“主页套图”时，默认交付一张头像和一张主页横幅；明确要求资料卡时再加入资料卡。三张图分别建立简报、生成、检查和归档，共享同一角色版本和品牌线索。

## 4. 文章封面

固定使用 `5:2` 横版。先从全文确定具体核心对象、它带来的关键变化、读者最该记住的结论和品牌角色，再只设计一个核心视觉叙事。

默认采用极简符号海报与精致二次元插画结合的风格。核心对象、标题、视觉隐喻和角色动作共同表达同一项变化；角色作为触发者、执行者或承受者直接作用于核心对象，并产生清楚可见的结果。主标题包含核心对象与关键变化，使用六至十六个中文字、最多两行；副标题只在能补充必要信息时使用。品牌为主题核心时，名称、logo、设计语言和品牌色进入第一视觉层；品牌只是案例或来源时只作为辅助信息出现。全图使用二至四种主色，只保留一个视觉中心和必要文字。选择极简手绘内容视觉后，标题与场景共享同一片留白，不再叠加精致二次元渲染、完整背景或海报装饰层。

## 5. 说明图

默认使用 `4:5`；方形社交卡使用 `1:1`；纵向路径可用 `3:4`；横向对比或系统关系可用 `16:9`。只选择对比、流程、系统关系、矩阵、问题到结果、时间线、漏斗或组合关系中的一种主要结构。

默认按“主标题 → 核心结构 → 三至五个关键模块 → 一句结论”组织。标题包含准确的产品、项目或核心概念名称，最多两行；模块只保留短标题、必要数字和一句极短说明。角色成为结构中的行动节点：接收输入、执行关键动作、传递结果，或者做出会改变路径的选择。位置、大小、颜色和连线共同形成手机端可顺畅读完的顺序。配色优先服从核心品牌，其次服从内容逻辑，使用二至五种主色。选择极简手绘内容视觉后，三至五个节点必须落在同一个装置、路径或物理互动中，不拆成三至五张卡片。

## 6. 正文插图

固定使用 `16:9` 横版，一张图只解释当前段落或章节最值得图像化的一项关系或变化。在概念隐喻、简洁流程、结构关系、对比构图和局部场景中选择一种表达方式；只有内容确实需要时才使用三至五个步骤或模块。

默认采用轻量概念图解与二次元插画结合的风格，重点表现对象怎样连接、分工、转换、冲突或改变结果。角色亲自移动、连接、拆分、选择、阻挡或转换对象，或者让机制对角色造成可见的前后状态变化。文字可以省略；确有必要时只使用一个短标题、二至五个短标签，以及必要数字、比例或专有名词。画面在解释清楚这一项内容时停止。选择极简手绘内容视觉后，优先使用一个物理隐喻场景；只有关系本身无法由单一动作表达时，才使用连续流程或并置对比。

## 7. 整篇文章配图组

用户要求给整篇文章配图时，先规划全组，不按段落机械出图，也不先假定四张或八张。运行：

```text
python scripts/visual_kit.py plan-schema
python scripts/visual_kit.py plan-draft <plan-path> --set-id <slug> --language <language>
```

阅读全文，找出只有图像化后才会明显降低理解成本的认知锚点。每项必须记录互不重复的核心关系、应该插在哪段之后，以及能在原文中按顺序找到的 `source_excerpt`；数量由真实锚点决定。相邻图片不能重复解释同一结论，纯装饰、换句话说和没有角色作用空间的段落不进入计划。

根据关系选择结构：变化过程或步骤用 `process`，前后差异用 `comparison`，对象间依赖用 `structural-relation`，抽象判断用 `conceptual-metaphor`，具体情境用 `local-scene`。物件、动作和空间关系必须从当前文章重新创造，不从风格案例复制固定物件池。

完成计划后运行：

```text
python scripts/visual_kit.py materialize-plan <plan-path> --output <ordered-brief-directory>
```

脚本验证原文片段与顺序，为每个锚点生成现有 `article-illustration` 简报。按返回顺序逐张运行 `prompt`、实际生图、看图、`finalize` 和 `check`；每张仍遵守单图合同，不建立第二套文章插图提示格式。全部通过后运行：

```text
python scripts/visual_kit.py finalize-set <character-kit> --plan <plan-path>
python scripts/visual_kit.py check-set <article-set-folder> --kit <character-kit>
```

文章配图组记录正文顺序、插入位置、原文锚点和它实际消费的每一个 visual revision。任何单图的内容与计划不一致、缺失或未通过检查时，整组不能归档完成。

## 8. 自动检查与重试

生成后实际打开图片，先缩小到社交信息流尺寸检查第一眼层级，再用 100% 尺寸检查边缘和接触。按下面顺序检查：

1. 角色的轮廓、脸部、主配色、服装连接和标志物与当前档案及主参考图一致。
2. 核心对象、机制或变化、结论和品牌角色与内容真源一致。
3. 角色动作确实改变对象、路径或结果；移开角色后，封面叙事、说明结构或插图关系会缺少一段必要因果。
4. 画面只使用简报选定的一种主要结构，阅读顺序在缩略图和手机尺寸仍成立。
5. 标题、数字、专有名词、标签和 logo 可辨认，且没有捏造内容真源之外的信息。
6. 肢体、连接、边缘、遮挡和背景没有明显生成错误；角色与环境共享光线、透视、景深、颗粒、反射和接触阴影。

极简手绘内容视觉再做四项减法检查：隐藏全部文字后，动作和结果是否仍能被看懂；缩成缩略图后，角色、对象和流向是否仍是前三个视觉重点；删除任一装饰后，含义是否完全不受影响；画面是否出现卡片、面板、完整环境或渐变阴影。前三项失败时重新选择动作或物件，最后一项出现时删除对应视觉层并从原始简报重生，不在失败图上继续堆说明。

OKX Editorial 再检查绿色是否只落在重点、logo 是否直接来自透明资产、画面是否只采用一种主场景，以及角色是否出现白边、毛边、漂浮感或独立清晰度。前两项失败时修正品牌和文字输入，后两项失败时修正场景层级、共同光线、遮挡与接触关系，再从原始角色和内容资料重生。

不通过时先修正视觉简报中最早的错误判断，再从角色档案和原始资料重新生成，不以失败图连续衍生。需要改变事实、叙事重点或角色固定特征时，返回 `SKILL.md` 的主流程处理取舍。

## 9. 已归档视觉的无损修订

用户要求“删标题，其它不变”“改错字”“调整动作”或“换重点”时，先读取 visual 根目录的 `current.json`、当前 revision 的 `visual-record.json`、视觉简报和最终图片，再选择唯一修订范围：

- `local-rendering`：删除或替换局部文字、修明显渲染错误、轻调局部位置；上一版成图是编辑底图，未点名内容保持不变。
- `content-structure`：核心重点、动作因果、构图结构或文字层级发生变化；从内容真源和角色真源按新简报重做，上一版只校准连续性。
- `character-revision`：固定角色特征已正式升版；新主参考图是身份真源，旧成图只保留当前视觉的用途和节奏。

先修改同一个 visual-id 的简报，再运行：

```text
python scripts/visual_kit.py revision-prompt <character-kit> --visual <visual-folder> --brief <revised-brief> --change-scope <scope> --note <exact-change>
```

用返回的 `prompt` 和有序 `image_references` 实际编辑或重生，其中第二张输入固定为上一版成图。检查通过后运行：

```text
python scripts/visual_kit.py revise <character-kit> --visual <visual-folder> --brief <revised-brief> --image <approved-image> --change-scope <scope> --note <exact-change>
python scripts/visual_kit.py check <visual-folder> --kit <character-kit>
```

每次修订创建 `r002`、`r003` 等新目录，旧 revision 与生成输入继续保留。不要覆盖旧图，也不要另建一个失去父版本关系的新 visual-id。角色未升版时不能使用 `character-revision`，角色已经改变时也不能把它伪装成局部修图。

旧版平铺目录不属于正常运行合同。发现 `<visual-folder>/visual-record.json` 而没有 `current.json` 时，只能显式运行一次：

```text
python scripts/visual_kit.py migrate-visual <visual-folder> --kit <character-kit>
```

迁移把旧结果变成 `r001`，并把原平铺目录移动到同级 `.ip-studio-legacy-archives/` 保留。迁移完成后，`prompt`、`revise`、`check` 和文章配图组只消费版本化结构，不维护两套读取逻辑。

## 10. 归档与停止

用户批准或已经授权 Agent 代为定稿后运行：

```text
python scripts/visual_kit.py finalize <character-kit> --brief <brief-path> --image <approved-image>
python scripts/visual_kit.py check <visual-folder> --kit <character-kit>
```

正式产物写入：

```text
<character-kit>/derivatives/<kind>/<visual-id>/
├── current.json
└── revisions/
    ├── r001/
    └── r002/
```
